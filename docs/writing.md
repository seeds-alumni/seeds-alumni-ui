# UI の日本語の書き方（表記規約）

SEEDS同窓会のすべてのサービス（SEEDS-ID の会員ポータル・会員管理システム、イベント、SEEDS TOTP、ホームページ）の画面に出す日本語の決まり。**この文書が正**で、各リポジトリの CLAUDE.md はここを指す（2026-11-12、ユーザーの指定）。

- 対象：画面の文言（題名・ボタン・ラベル・説明・表の列・知らせ）、API が返して画面に出るエラーの文、メール、ホームページの枠（メニュー・フッター・404 など）。コードのコメント・開発者向けの文書と、ホームページの記事（規約・お知らせ・団体の紹介。団体の文書として書いたもの）は対象外。ただし用語（§5・§6）はそろえる
- 部品の組み方（どの知らせを使うか・空の状態・フォームの組み方）は `catalog.md` §8。この文書は言葉の決まり
- `seeds-ui-check` が、避ける言い方（§4）の一部を検出する（`catalog.md` §6）

## 1. 基本方針

- 自然で簡潔、明瞭な日本語にする。実際の日本の商用ソフトウェアで使われていても違和感のない文にする
- AI が生成した文にありがちな、冗長な言い方・過剰な丁寧語・英語の直訳調・抽象的な言い方を避ける
- 同じものには、**どのサービスでも**同じ言葉を使う（§5・§6）。リポジトリをまたいで同じ内容を違う言い方にしない

## 2. 表記の原則

- 一文を短くする。1つの文で1つのことを言う
- 不必要な敬語を使わない（「〜させていただきます」「〜でございます」「〜いただけますと幸いです」）
- 主語や目的語を繰り返さない
- 「〜を行う」「〜の実施」などの冗長な名詞の言い方を避ける（「審査を行います」→「審査します」）
- 英語の直訳ではなく、日本語として自然な言い方を使う
- ユーザーにとって明確な言い方を優先する。システムの中の名前（テーブル名・API 名・ロールの識別子）を画面に出さない
- 必要のない説明や補足を足さない

### 2.1 文体と記号

| 項目 | 決まり | 例 |
|---|---|---|
| 文体 | 文は「です・ます」。題名・ラベル・ボタン・表の列・メニューは文にしない（名詞で終える） | 「申請を受け付けました。」／「会員番号」 |
| 句点 | 文には「。」を付ける（知らせ・説明・エラー）。題名・ラベル・ボタン・表の列・バッジには付けない | |
| お願い | 「〜してください」。「〜して下さい」「〜をお願いします」「〜をお願いいたします」は使わない | 「もう一度ログインしてください。」 |
| 疑問 | 確かめるダイアログは「〜しますか？」（全角の「？」） | 「お知らせを削除しますか？」 |
| 括弧・記号 | 和文の中は全角（（）「」：、・）。ラベルと値の区切りは全角の「：」 | 「会員番号（5桁）」「対象：会員」 |
| 英数字 | 半角。和文との間に半角スペースを入れる。句読点・括弧の隣と、固有名詞（SEEDS同窓会・SEEDSプログラム・SEEDSゼミ）の中は空けない | 「CSV をダウンロード」「Google でログイン」 |
| 数と単位 | 数字と数える単位（件・人・回・通・分・秒・円）の間に半角スペース。期・年度・日付・時刻は空けない | 「63 件」「3 人」「1期」「2026年度」 |
| 日時 | 画面は「2026/10/27 03:37」、日付だけは「2026/10/27」。曜日が要るときは「2026/10/27（火）」。メールとホームページの本文は「2026年10月27日（火）」でもよい | |
| 読み込み中など | 末尾は「…」（3点リーダー1つ） | 「読み込み中…」「保存しています…」 |
| 値がない | 「—」 | |
| 任意の項目 | ラベルの末尾に「（任意）」。必須には何も付けない（必須が少ないときだけ「（必須）」） | 「電話番号（任意）」 |

## 3. 部品ごとの決まり

### 画面の題名

- 短く、画面の目的が分かる名詞句にする（「会員一覧」「申請の審査」「イベントの編集」）
- 「画面」「ページ」を付けない
- 左のメニュー・パンくず・画面の題名は同じ言葉にする

### ボタン・リンク

- 短い語にする。操作を表す**漢語（名詞）で終え、「する」を付けない**（「保存」「削除」「承認」「却下」「入力」）。目的語を付けるときも同じ（「変更を保存」「会員証を再発行」「CSV をダウンロード」）（2026-11-12、ユーザーの指定）
- 漢語のない和語の操作は動詞のまま（「閉じる」「戻る」「申し込む」「読み取る」「外す」「選ぶ」）。漢語があるときは漢語にする（「消す」→「削除」、「送る」→「送信」、「始める」→「開始」）
- 「実行」「処理」「OK」「はい」だけにしない。何が起きるかを書く
- ほかに「キャンセル」（ダイアログを閉じる）、「前へ」「次へ」（ページ送り）、「ログイン」「ログアウト」
- タブ・メニュー・表示の切り替え（`.segmented`）・絞り込みの選択肢はボタンではないので名詞にする（「すべて」「審査中」「設定」）
- 確かめるダイアログのボタンは、問いの動詞と同じにする（「お知らせを削除しますか？」→「削除」／「キャンセル」）
- ページの名前で移るリンク（メニュー・「お知らせの一覧」「会員ポータル」）は、行き先のページの名前にする（名詞）
- 別のタブで開くリンクは、リンクの後ろに「（別のタブで開きます）」を付けるか、`aria-label` で伝える

### 説明文

- 操作を理解するのに必要な情報だけを書く。原則1〜2文
- 題名やラベルで分かることを繰り返さない（題名「会員証」の下に「あなたの会員証です。」と書かない）
- 「このページでは〜できます」「以下の内容について〜」で始めない。いきなり要点を書く

### 入力フォーム

- ラベルは入力項目の名前にする（「氏名」「メールアドレス」）。「〜を入力してください」をラベルにしない
- 形式・条件はラベルの補足（`hint`）に書く（「ハイフンなしの7桁」）。プレースホルダーは入力例か検索の対象だけにし、「例：」を付ける（「例：山田 太郎」）。必要な説明をプレースホルダーにだけ書かない（入力すると消えるため。`catalog.md` §8.3）
- ラベルとプレースホルダーで同じ言葉を繰り返さない
- 入力の誤りは、何が違うかと直し方を書く（「メールアドレスの形式が正しくありません。」「7桁の数字を入力してください。」）

### 表

- 列の名前は短い名詞（「氏名」「状態」「登録日」）
- 「〜情報」「〜内容」「〜一覧」など、要らない語を足さない（「会員情報」→「会員」、「申込内容」→「申込」。ただし画面・カードの題名としての「基本情報」は可）
- 同じデータ項目には、すべての画面・CSV の見出しで同じ名前を使う（§6）

### エラーメッセージ

- 何が起きたかを書き、必要なら次にすることを書く。「〜できませんでした。〜してください。」
- 技術的な言葉（ステータスコード・例外の名前・`Internal Server Error`・`null`）をそのまま出さない。調べるのに要る番号（申請番号など）は出してよい
- ユーザーを責める言い方にしない（「不正な入力です」→「〜の形式が正しくありません」）
- 「エラーが発生しました」だけで終えない。何ができなかったかを書く（「保存できませんでした。時間をおいて、もう一度お試しください。」）

### 成功メッセージ

- 終わった操作を短く伝える。「〜しました。」（「保存しました。」「申請を受け付けました。」）
- 「正常に処理が完了しました」「〜が完了いたしました」のような冗長な言い方を避ける

### 空の状態・読み込み

- 空の状態の題名（`.empty-state-title`）には「。」を付けず、説明の文には付ける。まだ1件もない：「〜はまだありません」。条件に当てはまらない：「条件に当てはまる〜はありません」（人なら「いません」）。分け方は `catalog.md` §8.4

### メール

- 件名は「【SEEDS同窓会】」で始め、何のメールかを短く書く（「【SEEDS同窓会】本登録の申請を受け付けました」）。イベントのメールは後ろにイベント名を付ける（「【SEEDS同窓会】申込を受け付けました：同窓生のつどい2026」）。開発環境では先頭に「[開発環境] 」が付く
- 本文も §2〜§4 に従う。冒頭の宛名は「〇〇 様」。結びの定型の挨拶（「何卒よろしくお願い申し上げます」）は付けない
- 末尾に「──」の線、送り主（大阪大学SEEDSプログラム同窓会）、返信できるかどうか（「このメールは送信専用です。返信してもお答えできません。」）を書く

## 4. 避ける言い方

原則として使わない（文脈上どうしても必要なときは例外）。★は `seeds-ui-check` が検出する。

| 避ける | 代わり |
|---|---|
| 〜することができます ★／〜を行うことができます ★ | 〜できます |
| 〜することが可能です ★／〜が可能です ★ | 〜できます |
| 〜の実施／〜を実施する | 〜する（「審査を実施」→「審査する」） |
| 〜を実行する ★ | 具体的な動詞（「同期する」「送る」。ボタンは「同期」「送信」） |
| 〜を行う／〜を行います ★ | 〜する（「審査を行います」→「審査します」） |
| 〜の管理を行う | 〜を管理する |
| 以下の内容について | （要らない。いきなり書く） |
| こちらから〜してください ★／こちら ★（リンクの文字） | リンクの行き先を書く（「会員ポータルで変更してください。」） |
| 〜するための機能 | （要らない。何ができるかを書く） |
| 正常に〜 ★ | （要らない。「保存しました。」） |
| 〜して下さい ★ | 〜してください |
| 〜させていただきます | 〜します |
| 〜いたします ★／〜でございます | 〜します／〜です |
| エラーが発生しました（だけで終える） | 何ができなかったかを書く |

## 7. AI への指示

- UI に出す日本語を書くときは、必ずこの文書に従う。新しい画面・部品を作るときも、既存の画面の言葉と用語に合わせる
- 実装が終わったら、変えた画面に出る日本語をすべて読み直す（セルフレビュー）。文法的に正しいだけでなく、商用のソフトウェアで使われていても違和感のない文にする。不自然な言い方は実装を終える前に直す
- 同じ内容をほかのリポジトリでも出しているときは（ログイン・会員証・エラー・メールなど）、そちらの言い方を探してそろえる
- この文書と食い違う既存の文言を見つけたら、直すか、ユーザーに知らせる
